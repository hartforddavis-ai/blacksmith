# 1. When KV cache fills with `--context-shift` enabled, which tokens are discarded and retained?

## QUOTED

From `llama.cpp` server README:

> "`--keep N` | number of tokens to keep from the initial prompt (default: 0, -1 = all)"
> ([GitHub][1])

From README parameter documentation:

> "`n_keep`: Specify the number of tokens from the prompt to retain when the context size is exceeded and tokens need to be discarded. The number excludes the BOS token."
> ([GitHub][2])

From completion documentation:

> "When the context window is full, some of the earlier tokens (half of the tokens after `--keep`) will be discarded. The context must then be re-evaluated before generation can resume."
> ([GitHub][3])

## INFERRED

The discarded region is the older portion of the context after the retained initial tokens. The retained portion is the first `--keep` tokens from the initial prompt.

# 2. What is the unit of `--keep`? What does `--keep 4` retain?

## QUOTED

> "`--keep N` | number of tokens to keep from the initial prompt (default: 0, -1 = all)"
> ([GitHub][1])

> "The number excludes the BOS token."
> ([GitHub][2])

## INFERRED

The unit is **tokens**, not messages.

`--keep 4` means retain the first four prompt tokens (excluding BOS), not four chat messages.

---

# 3. After a shift, does generation continue or stop?

## QUOTED

From completion documentation:

> "The context must then be re-evaluated before generation can resume."
> ([GitHub][3])

## INFERRED

With context shifting enabled, generation continues after the shift.

# 6. What happens with `--context-shift` disabled and cache full?

## QUOTED

Issue discussion:

> "If disabled:
>
> * Requests bigger than context window will result in an error.
> * `n_predict` for each sequence will be capped to `n_ctx - n_tokens_prompt`"
>   ([GitHub][7])

## INFERRED

Disabled context shift means the server does not discard old generation tokens to continue indefinitely.
