## Evidence

### QUOTED — `/api/generate` can apply templating

Ollama API documentation states:

> “Generate a response for a given prompt with a provided model.” ([GitHub][2])

For `/api/generate`, the documented parameters include:

> “template: the prompt template to use (overrides what is defined in the Modelfile)” ([GitHub][2])

and:

> “raw: if true no formatting will be applied to the prompt.” ([GitHub][2])

This means `/api/generate` is not inherently a raw-text-only path.

---

### QUOTED — source code shows template execution in `/api/generate`

Ollama source code shows the generate route has a direct template execution path:

> “Direct template execution flow.” ([GitHub][1])

The same source shows:

```go
if err := tmpl.Execute(&b, values); err != nil {
```

followed by:

```go
prompt = b.String()
```

([GitHub][1])

Therefore the source does not support the claim that renderer/template processing is chat-only.

---

### QUOTED — chat-like handling exists inside generate under conditions

The source comments:

> “check that we're in the `api/chat`-like flow, and if so, generate the prompt the same way” ([GitHub][1])

and:

> “TEMP(drifkin): we should really just detect the chat-like flow and call the real chat handler, but doing this as a stopgap to get renderer support for generate” ([GitHub][1])

This indicates some renderer/chat-template behaviour is also reachable from `/api/generate` in specific cases.
